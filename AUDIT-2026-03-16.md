## Issues Found & Fixed

### CRITICAL #0 — VITE_API_SECRET leaked to client bundle

| | |
|---|---|
| **File** | `src/cloudSync.ts:220-231` |
| **Severity** | CRITICAL |
| **Status** | FIXED |

**Root cause:** `import.meta.env.VITE_API_SECRET` was read in client-side code. Vite bundles all `VITE_`-prefixed env vars into the production JavaScript bundle. If `VITE_API_SECRET` was set in Netlify env vars, the secret was embedded in downloadable JS — anyone could extract it and call Netlify functions directly, bypassing Supabase JWT auth and rate limiting.

**Impact:** Complete auth bypass if the env var was set. Attacker could call `/api/claude`, `/api/gemini`, `/api/ocr` with the extracted secret.

**Fix:** Removed all `VITE_API_SECRET` references from client code. Auth now relies exclusively on Supabase JWT. The `API_SECRET` fallback remains server-side only in `_utils.ts`.

---

### CRITICAL #1 — Revision inflation on remote merge (cloud sync)

| | |
|---|---|
| **File** | `src/context/reducer.ts:850-867` |
| **Severity** | CRITICAL |
| **Status** | FIXED |

**Root cause:** `MERGE_PATIENTS_FROM_REMOTE` was missing from `REVISION_EXEMPT_ACTIONS`. When a remote patient with revision=5 replaced a local patient with revision=3, the revision-bumping wrapper detected clinical content changed and bumped the revision to 6.

**Impact:** Every remote patient accepted via sync got its revision incremented locally, then pushed back to the server. The remote peer fetched it, bumped it again — creating a ping-pong revision escalation. This is the likely root cause of cloud sync race conditions noted in CLAUDE.md.

**Fix:** Added `"MERGE_PATIENTS_FROM_REMOTE"` to `REVISION_EXEMPT_ACTIONS`.

### LOW #4 — `heparin` regex matches `enoxaparin`

| | |
|---|---|
| **File** | `src/engine/drugSafety.ts:40` |
| **Severity** | LOW |
| **Status** | FIXED |

**Root cause:** Pattern `/heparin|הפרין/i` — the string "enoxaparin" contains "heparin" as a substring. If any interaction were ever added using `heparin` as a key, patients on enoxaparin would also trigger it.

**Fix:** Changed to `/\bheparin\b|הפרין/i`.

---

### LOW #5 — `cipro` pattern inconsistency

| | |
|---|---|
| **File** | `src/engine/drugSafety.ts:30` |
| **Severity** | LOW |
| **Status** | FIXED |

**Root cause:** DRUG_PATTERNS used `/cipro/` without a negative lookahead, but ABX_EXTRACT_PATTERNS (line 656) used `/cipro(?!lex)/`. Without the lookahead, "cipralex" (escitalopram/SSRI) could trigger as ciprofloxacin.

**Fix:** Changed to `/cipro(?!lex)/` for consistency.

### LOW #6 — CSP connect-src overly permissive

| | |
|---|---|

| **Severity** | LOW |

## Areas That Passed Cleanly

### Clinical Engine — labDelta.ts (KDIGO AKI Staging)

- Baseline guard: `baseline <= 0 || peakCr < 0` → returns null. Solid.
- Ratio math: `peakCr / baseline` with baseline > 0 guard. Correct.
- Float precision: `Math.round(absoluteRise * 100) / 100` before 0.3 comparison. Handles IEEE754.
- Peak tracking: Uses `maxEntry` for staging, `peakEntry` for reporting. Recovery detection works.
- 48h check: `absoluteRise >= 0.3 && hoursElapsed <= 48`. Correct per KDIGO 2012.
- Stage 3 absolute: Requires BOTH `peakCr >= 4.0` AND `roundedRise >= 0.3`. Prevents stable CKD-5 false positives.

### Clinical Engine — rules.ts (Comfort Care)

- 40+ rule groups in `COMFORT_SUPPRESSED_GROUPS`. Comprehensive.
- `comfortRequiresExplicitTask` for procedures on explicit doctor order (bladder scan, retention).
- `comfortCareOnly` for palliative-specific rules (comfort sedation symptom checks).
- Detection uses structured `goalsOfCare === "comfort_only"` + regex fallback. Robust.
- Rules that SHOULD still fire in comfort care are correctly NOT suppressed (hypoglycemia, anaphylaxis, delirium, NPO).

### Clinical Engine — drugSafety.ts

- Drug patterns use regex with Hebrew+English variants. Good coverage.
- Beers criteria are age-gated (`minAge` field per rule).
- Renal dosing uses conservative CrCl (lower of female-55kg / male-70kg). Safe.
- Allergy cross-check with direct + cross-reactive severity tiers.
- 47 drug interaction pairs covering QT, bleeding, hyperkalemia, serotonin syndrome, nephrotoxicity.

### Clinical Engine — clinicalThresholds.ts

- Creatinine is `mode: "delta_only"` — prevents raw Cr from generating spurious critical badges.
- No duplicate thresholds found in rules.ts (rules use regex triggers, not lab value comparisons).

### Clinical Engine — mergeScan.ts

- 3-tier matching: strict (section+room+name) → loose (room+name) → stable (name+age).
- `consumedIds` set prevents double-matching.
- Whitespace normalization: `trim().replace(/\s+/g, " ")`.
- Manual tasks preserved across rescans. Generated task done state preserved.

### State Management — Reducer

- All 39 action types handled in switch with `default: return state`.
- `normalizePatient` covers all PatientEntry fields with defaults.
- `normalizeTask` covers all Task fields.
- Bed collision checked in all 4 relevant actions (EDIT_PATIENT, MOVE_PATIENT, NEW_ADMISSION, ADD_PATIENT).
- REAPPLY_RULES preserves done state and dismissed stubs survive multiple calls.
- ARCHIVE_SHIFT strips `photos: []`, `photoIds: []`, `generatedTasks: []`.

### State Management — Zustand Store

- All 8 state slices have persistence subscriptions (patients, shiftHistory, darkMode, scanMode, events, unassignedTasks, showTomorrow, activeSection).
- Storage-full event dispatched on quota errors.
- Photo migration async fire-and-forget on boot.

### Security

- `dangerouslySetInnerHTML` in exactly 1 place — always through `DOMPurify.sanitize()` with strict tag whitelist.
- Auth is fail-closed: Supabase timeout → check API_SECRET → 503 if both fail.
- Model whitelist in claude.ts: only 3 models allowed. max_tokens clamped 256-8192. Content-type whitelisted.
- No `as any` in engine/ or context/ directories.
- No secrets in VITE_-prefixed env vars (only VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY — both public).
- CSP: script-src 'self' only, frame-ancestors 'self', object-src 'none'.

### Cloud Sync

- Echo suppression via `lastPushedJson` comparison. Working.
- Debounce: 6s push window + 2.5s timer. Working.
- Exponential backoff: 2.5s × 2^attempt with ±20% jitter. Working.
- Per-patient revision tracking with `bumpRevision`. Working (after fix).
- Conflict detection: hash equality → revision comparison → user resolution.
